Read this first — three design realities the plan is built around

1. One BioAmp Candy = one channel. The Candy is a single-channel analog front end (72–720 Hz bandpass, fixed ×2420 gain, analog out to an ADC). A single channel can give you "muscle active vs. relaxed," not finger identity. Per-finger-ish output requires an array of channels over the forearm flexors/extensors — plan for 2 channels in week one and 4–6 for the real MVP. Even then, surface EMG at hobby fidelity resolves discrete gestures (fist, open, pinch, point…) far more reliably than continuous per-finger angles. The MVP therefore classifies a small gesture set and renders each gesture as a pre-authored hand pose; per-finger regression is explicitly a stretch goal.

2. The Quest should be a dumb renderer. Running a Kafka consumer (librdkafka) on Android/Quest is possible but painful and fragile. The plan inserts a tiny bridge service (Kafka consumer → WebSocket/UDP) so the headset only speaks a simple protocol. This also keeps all natKit logic on machines you can debug.

3. Defer the Coral. An EMG gesture classifier over a handful of channels is tiny (kB–MB of weights). Any laptop CPU classifies a 200 ms window in well under a millisecond. The Coral Dev Board adds int8 quantization + EdgeTPU compiler + a second Linux target for zero MVP benefit. It stays in the plan as an optional Phase 6 port with explicit "only if" criteria.

EMG window accumulation~100–150 msInherent: classifier needs a window (e.g. 200 ms window, 50 ms hop → effective ~100 ms group delay). Biggest single cost; tune window/hop.
