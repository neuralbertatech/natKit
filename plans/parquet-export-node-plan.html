Parquet Export Node

A first-class export node on the Visual Programming canvas. Wire a data stream into it and an experiment’s markers output into it, press Download, and the C++ backend streams back one labeled Parquet file for the session window. The point of linking both is that the cue timeline becomes a label column on the exported frames — the file that lands in your downloads folder is already analysis-ready.

Status: BUILT & verified end-to-end (July 28 2026)

Why this shape

The first cut of this feature ran the export as a Python control-plane job. That was wrong: it bought one skipped apt dependency at the cost of a permanent language boundary, an extra service in the request path, and a file the user then had to dig out of a volume. Reworked to run entirely in the C++ backend. The audit that drove the rework — nearly all of it already existed:

CapabilityWhere it already lives
The data + markers jointhe topic-aware combine node. It fans a data stream and an experiment’s markers into ONE channel: Data/<id> and Marker/<id> share a stream id. Per the source comment: “Data/<out> and Marker/<out> collide on id by design — that IS the bundle.”
Interval stitching (which cue owns a frame)nat::core::assignIntervalsToTimeline (StreamStitch.cpp), already C++ and already exposed through the C ABI — natVR’s assign_marker_intervals is a ctypes wrapper over it. Doing this in C++ removes a layer rather than duplicating one.
Historical Kafka readsBrokerMessagingQueue::startConsumer(startOffset) / createMessenger(topic, start_offset) with OFFSET_BEGINNING, added by the Kafka ABI work
HTTP surfaceNatKitBackend.cpp is already full of drogon handlers behind auth_manager.authenticateRequest
Sensor-agnostic frame projectionthe canonical channel-frame contract read through a DataSchemaDescriptor — the descriptor exposes a synthetic channels.N.samples view over whatever the schema actually stores

The only genuinely new thing was a Parquet encoder. Arrow is not in Debian bookworm’s default repos, so the backend image adds Apache’s own APT source and libparquet-dev (24.0.0).

Decisions

  • 1. Everything runs in the C++ backend. No Python in the export path, no control-plane hop. The cost is one apt dependency in the backend image; that is cheap next to a language boundary. reworked
  • 2. The join is the existing combine node. No new node kind and no new schema. Export can also be fed a data stream and an experiment as two separate inputs — the endpoint takes an optional marker_stream_id — so a combine is convenient, not mandatory.
  • 3. Export is “materialize a stream to a file”. The endpoint is generic per-channel (GET /api/export/parquet?stream_id=…), not experiment-specific. A plain data stream exports too; it just has no label values.
  • 4. Browser download, not a server-side artifact. The file is written to a temp path, read back, unlinked, and returned as an attachment. No /exports volume, no bind mount, no podman cp.
  • 5. The cue label is joined onto the frames as a configurable column (default label), plus <label>_cue_id and <label>_phase. Frames between cues are null — inside the session but not inside a cue. Channel labels, session id and window travel as Parquet key-value metadata (requires ArrowWriterProperties::store_schema(), which is easy to miss: without it Arrow silently drops the table metadata on write).
  • 6. Parquet support is optional at build time. find_package(Parquet) gates a NATKIT_HAVE_PARQUET define; without libparquet-dev the backend still builds and the endpoint answers 501 with a clear message rather than failing the build.

Known limits

  • Draining a live stream is time-bounded, not offset-bounded. Records keep arriving, so the idle window never fires. A hard maxDurationMs (30s) bounds it; the response sets X-Natkit-Truncated: true and the UI says so explicitly. The correct fix is to stop at the high watermark as of request time, which the messenger API does not currently expose.
  • Only canonical numeric channel frames export. Verified against the live IMU stream: 197,181 NatImuBulkDataSchema records read, none matched the contract, and the endpoint said exactly that. A classification or feature-vector stream is likewise not exportable.
  • Broker retention bounds everything. Export reads Kafka, so a session older than retention is partly or wholly gone.
  • Label granularity is per frame, not per sample: a cue boundary falling mid-frame attributes the whole frame to one label.
  • The whole file is buffered in memory on the way out (written to temp, read back, returned). Fine for session-sized exports; a very large one should stream.
  • The label lives in the file, not the stream. Putting it in the stream needs a new schema — NatSignalFrameDataSchemaV1 is numeric channels with nowhere to put a string class. Deferred; would make the label visible live and shareable with the classify path for train/serve parity.
