Descriptor-Driven Transform Plan

Replace the current EMG-specific Stream Viewer transform path with a generic descriptor-driven transform system that can inspect stream structure through DataSchemaDescriptor, validate transform input requirements, normalize compatible records into a shared channel-frame model, and emit one shared transformed-frame schema for reusable derived streams.

Scope: libnatkit-core transform contracts and derived schema design, Stream Viewer backend worker refactor, compatibility checks, and frontend protocol follow-on.

Decision

  • Move transform compatibility and field access onto DataSchemaDescriptor instead of hardcoding record-class branches inside the Stream Viewer transform worker.
  • Start generic transform output strategy with one shared core-owned transformed-frame schema for numeric multi-channel derived streams.
  • Name that shared output record NatSignalFrameDataSchemaV1.
  • Allow transforms to chain over intermediate derived streams as long as the source descriptor exposes the required fields by path.
  • Treat transform kind, configuration, lineage, and provenance as metadata concerns in the first slice rather than creating a distinct DATA schema per transform kind.
  • Keep the first algorithm set small: band-pass envelope and high-pass rectify are enough to prove the model.

Why This Exists

Current state

  • The Transforms tab is wired around EMG-specific actions such as create_emg_transform.
  • The backend transform worker accepts only EXG/EMG schema classes directly.
  • The current derived output path emits an EMG-specific transformed record type.

Target state

  • Transforms declare required inputs in terms of descriptor paths and field types.
  • Any stream with a compatible descriptor can use the transform.
  • Derived streams chain through one shared transformed-frame contract.

Constraint

  • Field semantics must stay in core descriptors, not ad hoc backend JSON rules.
  • Intermediate streams must remain replayable and inspectable like any other channel data.
  • The first slice should solve genericity for channel-based numeric transforms without trying to cover all future transform families.

First Transform Contract

The first generic transform proof should be a channel-based numeric transform. The initial required field contract for band-pass envelope is:

  • sample_rate_hz as a scalar numeric field.
  • channels.N.label as optional but preferred display identity.
  • channels.N.samples.M as the per-channel sample arrays.

Any source descriptor that can satisfy those requirements should be considered compatible, including raw source frames and intermediate transformed frames that preserve the same channel-frame shape.

Shared Output Strategy

The first output strategy should not create a new schema name for every transform kind. Instead, define one shared transformed-frame schema in libnatkit-core for numeric multi-channel derived frames.

Concern Decision Reason
Output schema count One shared transformed-frame schema: NatSignalFrameDataSchemaV1 Keeps transform chaining and generic tooling on one stable contract
Transform identity Metadata, not schema suffix Band-pass envelope and high-pass rectify should not require separate data contracts
Intermediate streams Reuse the same shared schema Avoid multiplying one-off schemas through multi-stage pipelines
Future special cases Allow transform-specific schemas later Only when a transform truly changes the field model, not merely the values

The first pass should deliberately preserve the useful parts of the current transformed EMG frame shape: device identity, producer time, per-channel labels, per-channel sample counts, and flattened numeric samples. The main change is to remove EMG-specific naming from the schema contract so the same record type can carry derived numeric frames from any compatible source descriptor.

Shared Schema Name And Field Set

The shared derived-frame output record should be named NatSignalFrameDataSchemaV1. The first-pass JSON payload version should be nat.signal.frame.data.v1.

Field Type Role
schema_version string Wire payload version string, initially nat.signal.frame.data.v1
device_id string Upstream producer identity carried forward for continuity with existing capture and replay flows
seq_no uint64 Monotonic frame sequence number propagated from the source or derived worker frame progression
device_ts_us uint64 Canonical producer-time join key for replay, stitching, and downstream alignment
n_channels uint32 Declared channel count for the frame
samples_per_channel uint32 Declared sample count for each channel frame slice
sample_rate_hz uint32 Per-channel sample rate needed for downstream DSP and compatibility checks
channel_labels string[] Per-channel identity labels preserved across transform stages where available
payload float32[][] Per-channel numeric sample arrays encoded as channel-major frame data

The corresponding descriptor should expose the same path model already proven in the EMG descriptors: 

device_id
seq_no
device_ts_us
sample_rate_hz
channels.N.label
channels.N.samples.M

That path continuity is intentional. The first generic transform worker should be able to consume raw EMG frames and NatSignalFrameDataSchemaV1 records through the same normalized reader without inventing a second path vocabulary for intermediate streams.

Architecture Direction

source topic
  -> decode typed Schema
  -> find DataSchemaDescriptor by schema name
  -> validate transform requirements by descriptor path
  -> normalize into shared channel-frame view
  -> run transform algorithm
  -> emit shared transformed-frame schema
  -> expose descriptor for downstream transforms and UI

The normalization layer is the key boundary. The DSP algorithm should consume a generic in-memory frame model, not an EXG-specific record class.

Implementation Phases

New plan · initial direction captured on 2026-07-03
  • Phase 1 · Transform contract: define the backend transform requirement model in terms of descriptor paths, expected field types, and normalization rules.
  • Phase 2 · Shared derived schema: add NatSignalFrameDataSchemaV1 plus its descriptor for numeric channel-based derived streams, keeping the established channels.N.label and channels.N.samples.M access pattern.
  • Phase 3 · Descriptor-driven reader: replace direct EMG record branching in the Stream Viewer transform worker with descriptor lookup, compatibility validation, and normalized frame extraction.
  • Phase 4 · First generic algorithms: port band-pass envelope and high-pass rectify to run on the normalized frame model and emit the shared derived schema.
  • Phase 4.5 · EMG transform cutover: migrate the current ExgPillEmgTransformDataSchemaV1 path toward NatSignalFrameDataSchemaV1 as the preferred derived output contract, with any short-lived compatibility bridge kept explicit and disposable.
  • Phase 5 · Protocol cleanup: generalize the WebSocket actions and frontend model away from create_emg_transform toward generic transform requests and transform capability discovery.
  • Phase 6 · Chaining proof: verify that a transform can consume a previously transformed stream through the same descriptor-driven path without record-class special cases.
  • Phase 7 · Validation and tests: add coverage for missing descriptors, missing required paths, wrong field types, compatible raw input, compatible intermediate input, and incompatible stream rejection.

Open Questions

  • Which provenance fields should live on the derived data record versus companion metadata records.
  • Should seq_no on NatSignalFrameDataSchemaV1 always preserve the upstream frame sequence when there is a one-to-one transform, or should multi-input or windowed transforms reserve the right to assign a new worker-owned sequence.
  • Do we want to add an optional value_type or equivalent descriptor metadata early, even though the first shared schema is explicitly float32 payload output.
  • Whether the first compatibility layer should support only channel-array inputs or also alternate descriptor layouts through explicit mapping rules.
  • How much of transform capability discovery should be pushed into the frontend in the first slice versus staying backend-driven.

What Not To Do

  • Do not keep growing the EMG-specific transform worker and call it generic later.
  • Do not encode transform compatibility as handwritten schema-name allowlists when descriptor paths can express the actual requirement.
  • Do not create a new output schema per transform kind unless the field model genuinely changes.
  • Do not let intermediate transform streams become second-class records that bypass descriptors.
This plan intentionally starts with the shared transformed-frame output strategy because that is the cleanest way to make descriptor-driven transform chaining work without turning every DSP step into a schema proliferation problem.
