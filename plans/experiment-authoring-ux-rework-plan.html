Experiment Authoring UX Rework

Authoring an experiment currently means fighting a 320px floating strip full of unlabeled inputs. This plan reworks the experience in layers: fix the fields (done), give authoring a real surface, add a quick setup that turns a pile of images into a runnable protocol, and eventually make the protocol spatial — steps as nodes, repeat groups as black boxes you zoom into — without undoing the experiment-as-entity model that the history/snapshot work deliberately built.

Status: Phases 1–2 SHIPPED · open questions resolved · Phases 3–5 PROPOSED

The layered idea

Altitude 0  Quick setup      "here are 5 images, 3 reps, 2s holds"  -> generates steps
Altitude 1  Step list        ordered, labeled cards; tweak text/timing/media
Altitude 2  Step detail      media, tutorial flags, wait barriers, seeds
Altitude 3  (later) Canvas   steps as nodes, repeat groups as zoomable containers

Every altitude reads and writes the same StepProtocol (experimentSteps.ts). Quick setup is a generator with a saved recipe, the step list is an editor, the canvas is a projection. One runtime shape means the runner, markers, recording, instances and training never care which altitude authored the protocol. This is the same trick stepsFromLegacyProtocol() already plays.

What is wrong today (observed, not guessed)

  • The surface is 320px wide. .graph-experiment-panel is a floating strip on the canvas; each step row wraps 6+ controls onto 2–3 cramped lines. The ADL protocol is 30 rows of this.
  • Fields were anonymous. Placeholder-only inputs: a filled cue row showed count_1 | count_1 twice with nothing saying which is display text and which is the trained class label. (Fixed in Phase 1.)
  • One altitude. Identity, protocol minutiae, built-ins, record controls and history all stack in one scroll column. Record had to become a sticky footer just to stay findable.
  • Structure is invisible. A shuffled ×3 repeat group is an indented list; the compiled timeline exists only as the text "24 steps · ~96s".
  • Cold start is the full editor. A new user must understand steps, cues, classes, rest classes and tutorial flags before they can record anything.

Non-negotiables (decisions already locked elsewhere)

  • The experiment stays an entity, not a node. The history-snapshots plan deliberately moved it off the canvas; instances/forks/binding all hang off that. This rework changes where the protocol is authored, never the ownership model.
  • The markers node stays wired data. Combine's marker lane, the viewer overlay and the export label join depend on it. It becomes the portal to the experiment (Phase 4), not a config surface.
  • Everything compiles to EmgCueEvent[] — runner, markers, resolveScheduleWaits(), instances and training stay untouched by all phases.

Phase 1 — Fix the fields SHIPPED 2026-08-07

All inside the existing panel; verified with svelte-check (0 errors), vitest (79/79, two new tests), and live headless-browser screenshots against the dev stack (scratch data, cleaned up).

  • Every step field has a label: Step type / Shown to participant / Class label (trained on) / Hold (s) / Duration (s) / Continue-button text / Times / Shuffle each pass / Tutorial (not trained on).
  • Instructions can hold for input. InstructionStep gained wait_for_input + continue_label; the toggle swaps the Duration field for the button text. Compiles to the same zero-length barrier a wait step emits, so the runner, the clock-freeze and marker resolution needed zero changes. The standalone wait kind survives for existing protocols.
  • Kind is visible at a glance: a colour-coded left border per step kind (instruction blue, cue green, rest slate, wait amber, repeat purple).
  • Duplicate step (deep-copies repeat groups with fresh ids) — build one cue/rest pair, stamp it.
  • Changing a step's kind no longer wipes it: text, duration and media carry over where the new kind supports them (retypeStep, swapped wholesale via replaceStep so old-kind fields don't linger).

Phase 2 — A real authoring surface: the Experiment Designer SHIPPED 2026-08-07

Move protocol authoring out of the strip into a wide overlay workspace (same presentation family as the composite-internals modal): open from the experiment pill and from an "Edit protocol" button. The floating panel shrinks to a status card — bound experiment, classes, duration, Record/Stop, live cue, history — which is what an operator actually needs mid-session.

  • Layout: compact header (name / participant / notes), the step list as full-width cards in the middle, and a compiled timeline strip pinned at the bottom — colored segments per class/phase rendered straight from compileStepProtocol(), with waits as barrier ticks and tutorial spans hatched. Edit a duration, watch the timeline change. (Same idiom as TimelineStrip.)
  • Repeat groups collapse to a one-line summary ("×3 · shuffled · 4 steps · ~48s").
  • Drag to reorder steps and drag in/out of repeat groups; keep the arrows as the accessible fallback.
  • Section separation: protocol authoring no longer shares a scroll column with built-ins and history (built-ins become templates in Phase 3's create flow).

Size: frontend-only, one new component + panel diet. No model or backend changes.

Phase 2.5 — Seeded randomization + step-type cleanup SHIPPED 2026-08-07

Everything random in a compiled schedule derives from a stored seed, so any schedule can be recreated from the protocol JSON alone — and rerolling a seed is how you get a new variation.

  • Timing jitter: timed steps (instruction/cue/rest) gained jitter_s — the duration is randomized ± that many seconds, drawn from a protocol-level seed's stream at compile time. Fixed rest lengths let participants anticipate the next cue; jitter breaks that, reproducibly. Barrier steps (waits) have no duration to jitter.
  • Seeds are visible: a shuffled repeat group shows its shuffle seed with a dice-reroll button; the designer header shows the protocol's timing seed with the same. The legacy fixed form also exposes its shuffle seed now.
  • Step types consolidated: the standalone wait kind left the palette — an instruction with "Wait for input" is the same barrier. Old protocols still load, run and display; retyping a wait to an instruction carries the toggle + button text so the conversion is behaviour-preserving.
  • Palette explains itself: add-step buttons carry the kind's colour dot and a tooltip saying what the kind is for ("the recorded class — what a classifier learns from"), matching the card accent colours.

Phase 3 — Quick setup: recipe in, protocol out

Flatten the learning curve: a new experiment starts from a template picker (Image cues / Gesture list / ADL tasks / Blank) and a recipe card with only high-level knobs. The flagship flow is "drop 5 images, press Record".

  • Image-cues recipe: a drop zone; each uploaded image becomes a class (label prefilled from the filename, editable), reusing the existing /api/media upload. Knobs: repetitions, hold s, rest s, lead-in s, shuffle, "practice pass first" (a tutorial repeat group), "wait for ready" (an instruction with wait_for_input).
  • Generator, not a new shape: the recipe compiles to a plain StepProtocol and is stored alongside it (protocol.quick_setup, opaque to the backend like the rest of the protocol). Reopening a recipe-backed experiment shows the recipe card; "Customize steps…" opens the Phase 2 designer and detaches the recipe with a confirm — regenerating over hand edits is the lie we refuse to tell.
  • Built-in protocols move here as templates in the create flow instead of a section pasted under the step editor.

Size: frontend-heavy; backend only if image labels want server-side filename metadata (they don't — original_name already comes back from /api/media).

Phase 4 — Spatial protocol canvas: zoom into the black boxes

The designer's step list becomes (optionally, a view toggle) a canvas of step nodes in a sequence lane. A repeat group renders as a container node — a black box showing its summary — and double-click zooms into it, opening its interior in place with a breadcrumb (Experiment ▸ Main block), exactly the mental model of zooming into composites on the main canvas.

  • Reuse the idioms, not the semantics: pan/zoom, node cards and the internals-overlay pattern come from StreamGraphEditor, but a protocol is control flow (an ordered sequence), not dataflow. Auto-layout in a lane, no free-form edge wiring — so nothing invalid can be drawn and there is no second graph model to validate.
  • The markers node is the portal: double-clicking it on the main canvas zooms into the bound experiment's protocol canvas. Spatially, the experiment lives "inside" the node that carries its markers — the data graph and the protocol graph become two altitudes of one space.
  • Selecting a step node opens its labeled Phase 1 fields in the inspector rail — detail on demand instead of every field on every row.

Size: the big one. Gate it on Phases 2–3 proving the model; the step list stays as the accessible/simple view.

Phase 5 (later) — Wiring experiments together

Once protocols are spatial, composition is natural: session blocks — whole protocols or repeat groups promoted to reusable blocks — chained on the same canvas (Tutorial → Ready gate → Block A → Break → Block B, counterbalanced variants, etc.), compiling by concatenation into one timeline. This is the "side menu becomes a little visual-programming sub-menu" idea, landed on top of the entity model instead of against it. Design sketch only; do not build until a real protocol needs it.

Open questions — RESOLVED (Zach, 2026-08-07)

  • Designer presentation: overlay in the VP page (shipped as such in Phase 2).
  • Recipe detach: hard detach with a confirm on first manual step edit — regeneration must never silently destroy hand edits.
  • Phase 4 scope: the canvas is a view toggle; the step list stays canonical for accessibility.
